(evidence: design-a.md:94-103 (D10), :587 ('Retry as a reward-hacking channel ... message capped'); execution/editor_tools.py:247; CLAUDE.md (service) Security Notes, 'Sandbox, fail closed' bullet; design-b.md:114-118 (D23).)

### Missing from both
- Where the combine ABAB re-test runs when kept trials mix package and no-package changes: point 1 requires 'same environment on both sides, differing only by the acquired package', so the base side must run in E0 and the combination in E(union lock); neither design says which env the A side of ABAB uses, and non-package keeps were judged against the ambient (Step 2) baseline, not E0.
- The ambient-vs-E0 gap: Step 2's baseline runs in whatever environment the engine was started from (launcher execvp on PATH, VIRTUAL_ENV passed through); E0 is built from L0. If the user's installed set differs from L0, the package gain is proven in E0/E1 and not in the user's real environment. Neither design measures or reports the ambient-vs-E0 ratio or refuses when it is outside the noise.
- Provenance of the resolver itself: both say 'pinned uv' (A adds 'version-checked'), but a version string is not a hash. Who installs uv for the fetch phase, from where, with which sha256, and what happens when the probe shows Landlock read confinement breaks uv (both mark it unverified; neither gives the fallback: refuse 3b on that host, or run with a weaker confinement and say so in the report).
- The `_env`/`_wheels` reality: they would be left behind, not swept (refnames.py:22); both plan to 'skip' them, but a dedicated cleanup owner for the venvs and wheelhouse (sizes up to ACQUIRE_MAX_BYTES, under the run lock, in `finally` and in sweep_stale_runs) is specified in neither §4.
- `--exclude-newer <now-14d>` combined with `-c <L0 pins>`: an L0 pin released within the last 14 days (or an L0 pin that is sdist-only) makes the resolve fail or require a build; only A mentions E0 sdists in prose and neither puts 'L0 itself violates the policy -> needs_user, with the pin named' in the test plan.
- Reproducer and held-out variants are produced by the same request, so an error report that steers the writer biases both; neither derives variants independently (a second request, or engine-made input perturbations of the public reproducer) nor states that the one allowed rewrite sees only the type/frame mismatch and never the trial's output (A says 'one rewrite' with no input spec; B's D23 is named but not applied to the rewrite explicitly).
- Retry conversation shape and its cost: neither says whether attempt 2 replays attempt 1's transcript (view outputs, cached prefix) or starts a fresh request with the feedback; the D9/D6 reservation and `retry_floor_usd` depend on which, and so does whether the attempt-1 context can carry the hypothesis fence token check again.
- Anti reward hacking for the heal fix beyond heal_tamper tokens: neither adds a capture rule that the fix may not add a new workload/entry point, a conftest-like hook under a non-protected name, or a `__init__.py` that changes import order of the reproducer's target; both lean on human review of the flagged branch, which is acceptable only if the report states it.
- Noise rule interaction with the env baseline: `env_baselines` is measured once per lock sha; neither states the N (MIN_RUNS) and the `noisy_host` check apply to E0 exactly as to the ambient baseline, nor that a trial whose E0 baseline was measured in an earlier round (host drift) is still comparable.
- A per-package 'imports it' proof is an AST scan via top_level.txt; neither handles dynamic imports (importlib, entry points) or a package used only through a plugin mechanism, so a genuinely used package can be dropped and the re-test then fails silently into 'dropped, no gain'; the report should name why a package was dropped.
